# SLG 小游戏 VibeCoding 提示词批次包

> 配套主文档：`../SLG小程序_VibeCoding提示词工程包.md`（设定、数值、合规的总纲）
> 本目录是**可直接投喂给 AI 的逐批次开发提示词**。

---

## 怎么用

每个批次**单开一个对话**，按下面顺序把内容贴给 AI：

```
1. 先发 B00_共享上下文.md 的全文       ← 每次都要发，防止 AI 失忆
2. 再发 当前批次文件（如 B05_...md）的全文
3. AI 输出后立刻跑单测，通过了再进下一批次
```

**为什么每个批次都要带 B00**：AI 的上下文会随代码量增长而被稀释，到第 3 个文件就可能忘记"数值零硬编码""服务器权威"这些铁律。B00 相当于每次重新注入项目宪法。

| 可并行 | 说明 |

| B04 ∥ B05 | 两人分工，无代码交集 |
| B09 ∥ B10 | PVE 内容与社交系统解耦 |

- B11 必须在 B10 之后（Bot 依赖小队/联盟接口才能填充社交）

## 每条提示词的固定结构

本包所有批次文件统一采用这个结构，缺一不可：

1. **任务** —— 一句话说清这个批次交付什么
2. **依赖与前置** —— 需要哪些批次已完成，以及需要哪些配置表就位
3. **必做清单** —— 拆到可执行的功能点
4. **输入 / 输出契约** —— 精确的接口签名、数据结构、错误码
5. **验收标准** —— 可执行的、带具体数字的验证项
6. **禁止项** —— 明确告诉 AI 别做什么（这比"要做什么"更能防止跑偏）
7. **开工提示词** —— 可直接复制粘贴给 AI 的启动语

---

## 一个提醒

如果 AI 在某个批次反复做不对，优先怀疑**提示词的验收标准不够具体**，而不是模型能力问题。把"要优化性能"改成"拖动地图 60 秒内存增长 < 10MB"，AI 的表现会有质的差别。
