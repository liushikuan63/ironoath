# 内城场景美术 · Vibe Coding 规格

> 用户要求（2026-09-19）：**内城应是真正类似中世纪城堡的场景，而不是当前网格布局。**
> 本文是 [对标开发包 V09](../SLG对标补充_VibeCoding开发包.md) 的场景专项规格，隶属 CC 阶段 3.2/4 与 B03，不另建玩法批次。
> 状态（2026-09-19 复审）：A16 概念/分层/热区稿、A17 三张舞台图和 A18 十五类建筑主体均已落地；
> A19 状态表达已用程序绘制覆盖选中/升级/可收取/暂停/空地，A20 轻量氛围仍是可选未做项。
> 客户端当前采用锚点投影而非均匀棋盘；完整 `CITY-ART-01~08` 仍以真跑截图逐条验收，不能由本节代替。

## 〇、现状与本次目标

`client/assets/scripts/scene/CityPanelView.ts:223` 创建网格，`:226` 遍历格位，`:389` 按选中建筑渲染详情，`:439` 在空格发起建造选择。当前可操作性以矩形建筑卡片、建筑图标与 6×6 格子表达；图标换成城堡图片也仍是棋盘，不满足新要求。

**一句话交付物**：进入内城先看到一座有城堡核心、城墙包围、道路联通、军政生产分区和高低层次的中世纪城镇；点击真实建筑轮廓进入现有操作，而非点击方格卡片。

**不变的部分**：B00 的原创低魔乱世、流亡王裔与铜金/暗红 UI、Cocos 2D 技术路线、服务器权威、现有建筑配置 ID/等级/产出/队列。中世纪石堡是本次明确的建筑视觉方向，不自动改写七大家族、武将姓名或经济数值。

## 一、画面要求：必须像城，而不是“网格换皮”

### 1.1 视觉基线

| 维度 | 必须满足 | 明确不接受 |
|---|---|---|
| 空间 | 固定斜俯视的 2D 分层场景，视觉上具有纵深；城堡高、街巷低、城墙围合；建筑有基座、接地阴影、体量差 | 等距矩形卡片、棋盘格线、36块同尺寸底板、透视不一致的图标拼贴 |
| 建筑 | 石砌主堡、垛口、塔楼、木石民用建筑、暗红旌旗、金属设施；写实比例、低魔冷兵器质感 | Q版膨胀城堡、现代楼宇、科幻能量塔、复制知名游戏城堡剪影或标志 |
| 构图 | 主堡为首要地标；城门—主路—广场—主堡形成可读主轴；左右支路连接功能区，边缘地形收束场景 | 所有建筑同样大、同样亮；让金币按钮或大弹窗长期盖住主堡 |
| 色彩/光照 | 石灰、暗铁、木褐为场景基底；铜金与暗红集中给王权/交互；统一左上主光、统一接地阴影方向 | 全图棕金糊成一片、每栋不同光向、把可采集和危险都画成红光 |
| 信息与交互 | 默认看城，选中建筑后才突出名称/等级/详情；待完成/暂停用小标识+可读文案，点击热区贴建筑 | 每栋常驻长文本、整屏进度条；建造空位默认全画成“+”方格；一张背景里烘焙假按钮 |

**推荐表现方案**：2D 斜俯视 Sprite 分层形成体积感；不是引入 3D 引擎、自由旋转相机或即时城民模拟。动画只做轻量局部反馈，静态场景先达到可读与可操作标准。

### 1.2 场景分区和视线引导

这是**构图目标**，不是新增建筑门槛或自动搬迁旧存档：

| 区域 | 构图职责 | 现有建筑候选 | 道路/地形关系 |
|---|---|---|---|
| 王庭高地 | 画面中上部主地标，台阶/内墙形成高差 | `main_city` | 主路经广场连接主堡，主堡轮廓不得被 HUD 截断 |
| 城门与军事区 | 下部入口可感知城防，军队集结有空间感 | `wall`、`barracks`、`stable`、`archery_range`、`siege_workshop`、`drill_ground` | 军营与校场相邻的视觉倾向；出征入口仍走真实世界地图链路 |
| 行政与民生区 | 相对安静、建筑体量小于王庭 | `academy`、`embassy`、`hospital`、`warehouse` | 支路连接主轴；医院救护符号原创，不使用受保护的红十字标志 |
| 城郊生产带 | 林缘、岩坡、田块使生产设施有环境语义 | `lumber_camp`、`quarry`、`farm`、`iron_mine` | 在城景边缘或外郭表达生产；不能改其现有“内城建筑”的实际归属/可达性 |
| 装饰与远景 | 山脊、远村、坡地、城垛制造纵深与尺度参照 | 无配置对应的纯装饰 | 不加产出、不计入建筑数、不表现成可点击功能楼；装饰不遮挡建筑热区 |

新账号只显示真正已建造的功能建筑；未建建筑不能预画在底图中冒充存在。允许静态城郭作为舞台，但承担可升级 `wall` 的功能城防节点必须与存档状态区分；装饰城墙不能暗示玩家已获得城墙防御收益。

## 二、15类建筑的美术交付映射

配置真源为 `contract/config/building.json`；本次现读 15 行，后续以配置行集核对，不把 15 永久写死在代码。

| configId | 场景轮廓要求 | 识别要素 |
|---|---|---|
| `main_city` | 高台石堡、主塔与内院，整体最高 | 王庭旗帜、宽阶梯，不把皇冠图标当建筑 |
| `lumber_camp` | 木棚、锯架与堆木，轮廓横向展开 | 木料，不新增可采伐树木玩法 |
| `quarry` | 低矮石棚与采石断面 | 岩块、绞架，与铁矿颜色/轮廓都不同 |
| `farm` | 不规则田块与谷仓小屋 | 作物畦纹属于地表图案，不成为可见建造棋盘 |
| `iron_mine` | 岩坡矿口、矿车与支护 | 深色矿石、矿口形状，不画魔法晶矿 |
| `warehouse` | 厚实仓库、封闭门廊与货堆 | 储藏用途，不与市场摊位混淆 |
| `barracks` | 军舍、营帐与武器架 | 集中营区入口 |
| `stable` | 长条马棚与小围场 | 饲槽/马匹剪影，不能遮挡入口 |
| `archery_range` | 射击棚、箭靶与长场地 | 箭靶朝向统一，区别于校场 |
| `siege_workshop` | 重型木工棚与攻城器半成品 | 大轮/杠杆形体，非现代工厂 |
| `drill_ground` | 开放训练场、围栏和队列标记 | 大面积空地，与有屋顶建筑形成节奏 |
| `hospital` | 民用救护院、浅色布棚与药草符号 | 非红十字的原创医疗符号 |
| `wall` | 可升级城门楼/城防段 | 与静态装饰城墙分层，状态变化不能污染整张底图 |
| `academy` | 石木书院、庭院、书卷纹饰 | 学术气质，避免魔法塔外形 |
| `embassy` | 礼仪门廊、会客院与旗杆 | 组织交流符号，旗面不复制现实/竞品徽记 |

**首批范围**：每类一套基础外形，状态用通用脚手架、光圈或标识组合，不能为每一级生成一套图。等级阶段化外观可后置；若提出三级外观，必须先明确切换等级与素材预算，不能由画师猜等级阈值。

## 三、分层、坐标与输入输出契约

### 3.1 渲染层与遮挡

由后向前建议：远景 → 地面/道路 → 后侧城墙 → 建筑阴影 → 建筑主体 → 前侧城墙/前景 → 状态标识 → HUD/详情。

- 同层建筑按基座落地点而不是图片中心排序；高塔可以视觉遮挡后方，但不能截断其唯一可点击入口。
- 建筑基座/道路连接点要一致，透明留白不参与点击；近景墙可淡化或避开可交互区域，不能抢触摸。
- 背景与建筑必须拆开交付；如果整体效果图里已经画了学院，运行时再叠学院会重影，也无法表达“未建”。
- 基地不可建水面、断崖等装饰不响应建造；合法空地在进入建造模式后才显示柔和轮廓与选址提示。

### 3.2 展示数据草案（实施前结合现有类型确定，不是已新增协议）

```text
SceneAnchor：稳定 anchorId、逻辑格位或现有建筑实例的映射、基座位置、道路接点、可建热区。
BuildingVisual：configId→spriteKey、pivot、基座/点击多边形、深度排序点、状态挂点。
BuildingState：现有服务端建筑实例、gridX/gridY、level、队列时刻、可操作性。
Selection：只存选中的真实实例/合法空地；操作继续回调现有 onUpgrade/onCollect 等入口。
```

坐标只做显示映射；不得重写服务器坐标、把视觉排序变成建筑 ID，或使取消操作悄悄落库。若现有 DTO 不提供状态原因，先追到领域与契约，不从图片颜色推断。

### 3.3 布局实现方案（实施前选择，不由美术擅改存档）

| 方案 | 收益 | 代价与边界 |
|---|---|---|
| A. **保留逻辑格位，投影为非均匀场景锚点（推荐）** | 不迁移存档，建造坐标与校验保持；玩家看到街巷，不看到网格 | 需要合法格位→热区的完整映射；旧城任意布局需验，不保证所有旧建筑恰好落在美术理想分区 |
| B. 按建筑语义绑定固定地标 | 王庭/军事/生产区构图最稳定 | 须明确玩家旧坐标与新选址的对应规则；多实例或可移动建筑可能冲突，不能静默丢弃 |
| C. 真正自由摆放与寻路 | 空间表达最自由 | 要改放置/碰撞/存档/权限与迁移，超出本次表现层改造，不建议首批 |

选择 A 时，网格仅是数据结构：**不允许把36个锚点仍均匀排成棋盘，再称为完成城景化。** 王庭构图与旧存档布局无法同时满足时，先报告可复现样例并裁决映射，不强制迁城或重排数据。

## 六、可失败的视觉与功能验收

| 验收 ID | 操作与判据 | 应判失败的反例 |
|---|---|---|

## 七、接续与场景同族检查
