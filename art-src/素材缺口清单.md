## 四、管线与验收（每族相同）

1. ImageGen 绿底（#00FF00）生成 → 原始图入 `generated/drafts/raw/<批次日>/`；
2. `python art-src/process_generated.py <清单.json>`：抠绿 → 去溢色 → 裁边 → 方形化 → LANCZOS；母版按绿色间隔带**投影拆格**（分段数≠网格数即报错，绝不静默等分）；
3. 判据（每条都能失败）：残留绿像素 ≤0.5% 否则非零码；母版拆格逐格非空且不粘连；每族目视抽检比对风格词（暗铁/铜金/暗红、无文字水印）；
4. 产物入 `generated/drafts/<族目录>/`，`manifest.json` `generatedPending` 登记，提示词记 `GENERATION_PROMPTS.md`；
5. **收编进包**（选定某族要接之后）：`python art-src/accept_to_runtime.py --drafts generated/drafts/<族目录> --out ../client/assets/resources/ui/generated/<运行时目录> --size 128`
   —— 改名（去 `gN-` 前缀、`_`→`-`、`v0`→`v1`，v1 即"已收编"）+ 缩放 + 调色板量化；
   `.png.meta` 由 **CLI 构建自己生成**（`--build` 会先开一次 asset-db 做导入），不必为收编专门开编辑器。

### 实测（舞台基准 1280×720）

| 候选 | 尺寸 | PNG | 解码内存 | 接缝 左右 / 上下 |
|---|---|---|---|---|
| 地表 tile | 1024² | 548.1KB | 4.00MB | 13.6 / 13.6 |
| 地表 tile | **512²** | **132.2KB** | **1.00MB** | 13.1 / 12.4 |
| 城墙 band | 1536×1024 | 421.6KB | 6.00MB | 13.7 / 4.9 |
| 城墙 band | **768×512** | **112.6KB** | **1.50MB** | 14.8 / 4.0 |
| 远景山脊 | 1024²（**要求 2560×1080，生成器没给**） | 185.8KB | 4.00MB | 20.6 / 68.6 |

### 结论（下一轮照此定尺寸）

1. **包体不是瓶颈**：地表 512² + 城墙 768×512 + 山脊 1024² 合计 **约 431KB PNG / 约 6.5MB 解码**。
   分包现 1.381MiB ⇒ 进包后约 1.80MiB（+31%）；解码 6.5MB 对 300MB 客户端内存预算可忽略。
   ⇒ **A18（15 类建筑主体）才是真正要省的那一笔**，舞台底图不必为字节牺牲尺寸。
2. **"铺满舞台需 N 张"是覆盖次数，不是内存**：重复纹理在显存里只有一份，别把这一列当成本。
3. **地表图真的能平铺**：对边差 12~14（阈值 24），且**换成 RGB 判据后仍然过**
   （灰度判据会漏"亮度相同但色相跳"的缝，那种缝在引擎里是一条彩带）⇒ 512² 可用作平铺单元。
   城墙带横向也能接（左右 13~15），可作可重复城郭段。
4. **判据可失败已植入**：把地表图右半整体错位 200px ⇒ 左右接缝读数从 13.1 跳到 **73.4**、
   上下仍 8.9（未误伤）、退 1 并点名"自称可平铺但对边对不上"；还原后复跑退 0。

### 更正上一格的量具口径缺陷，并记一次我自己的误删与恢复
